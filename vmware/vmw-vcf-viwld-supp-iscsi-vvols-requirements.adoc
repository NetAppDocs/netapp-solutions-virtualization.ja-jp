= ワークロードドメインにおけるiSCSI vVols の導入要件
:hardbreaks:
:allow-uri-read: 
:nofooter: 
:icons: font
:linkattrs:

[role="lead"]
VMware Cloud Foundationワークロードドメインに iSCSI vVols を導入するための推奨ネットワーク設計とインフラストラクチャ要件を確認してください。完全に構成された ONTAP AFF または ASA ストレージシステム、完成済みの VCF 管理ドメイン、および既存のワークロードドメインが必要です。



[[infrastructure-requirements]]
== インフラストラクチャ要件

次のコンポーネントと構成が適切であることを確認してください。

* ストレージ トラフィック専用のイーサネット スイッチ上に物理データ ポートを備えたONTAP AFFまたはASAストレージ システム。
* VCF 管理ドメインの展開が完了し、vSphere クライアントにアクセスできるようになりました。
* ワークロードドメインは既にデプロイ済みです。




[[recommended-iscsi-network-design]]
== 推奨されるiSCSIネットワーク設計

iSCSI には完全に冗長化されたネットワーク設計を構成する必要があります。次の図は冗長構成の例を示しています。ストレージ システム、スイッチ、ネットワーク アダプタ、およびホスト システムにフォールト トレランスを提供します。詳細については、 NetApplink:https://docs.netapp.com/us-en/ontap/san-config/index.html["SAN構成に関するリファレンス"^] 。

image:vmware-vcf-asa-074.png["iSCSIネットワーク設計"]

{nbsp}

複数のパスにわたるマルチパスとフェイルオーバーを実現するには、iSCSI 構成内のすべての SVM に対して、個別のイーサネット ネットワークにストレージ ノードごとに少なくとも 2 つの LIF を作成します。


NOTE: 同じ IP ネットワーク上に複数の VMkernel アダプタが構成されている状況では、ESXi ホスト上でソフトウェア iSCSI ポート バインディングを使用して、アダプタ間のロード バランシングが確実に行われるようにしてください。KB 記事 link:https://knowledge.broadcom.com/external/article?legacyId=2038869["ソフトウェア iSCSI ポート バインディングの使用に関する考慮事項（vSphere ホスト）"^] を参照してください。
