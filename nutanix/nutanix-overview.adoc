= NetApp ONTAPストレージを使用したNutanix Cloud Platformについて
:hardbreaks:
:allow-uri-read: 
:nofooter: 
:icons: font
:linkattrs: 
:imagesdir: ../media/


[role="lead"]
Nutanix Cloud PlatformとNetApp ONTAPストレージの組み合わせは、Nutanixのコンピューティングとは独立してストレージ容量とパフォーマンスを拡張できる、分離型アーキテクチャを提供します。デプロイする前に、アーキテクチャ、サポートされている構成、および留意すべき要件について確認してください。

ONTAPは、Nutanix仮想マシンワークロードをホストするための、拡張性と回復力に優れたストレージプラットフォームを提供し、組織がストレージ管理を簡素化しながら、容量利用率、パフォーマンス、およびデータ保護を最適化できるようにします。

NutanixコンピューティングとONTAPストレージを組み合わせることで、お客様は一貫した運用モデルを維持しながら、エンタープライズクラスのストレージサービス、柔軟なデータ管理、シームレスな拡張性を活用できます。このソリューションは、Storage Virtual Machine（SVM）、FlexVolボリューム、エクスポートポリシー、NFSデータストアなどの使い慣れたストレージの概念を使用しており、管理者は確立されたONTAPのツールと手順を使用してストレージを導入および管理できます。この統合により、Nutanix AHVハイパーバイザーはONTAPの成熟したデータサービスを活用できるようになり、同時に仮想化環境向けの柔軟で効率的なインフラストラクチャを提供します。



[[introduction]]
== はじめに

組織がNutanix Cloud Platformを評価している理由、それによって生じる可能性のあるコンピューティングとストレージのスケーリングの課題、そしてNetApp ONTAP外部ストレージがその課題をどのように解決するかについて説明します。



[[why-organizations-are-reassessing-virtualization]]
=== 組織が仮想化を再評価している理由

BroadcomによるVMwareの買収後、仮想化の状況は大きく変化し、多くの組織が長期的なインフラストラクチャとクラウド戦略の見直しを迫られています。企業が近代化への取り組みを進めるにあたり、既存のワークロードへの影響を最小限に抑えつつ、運用の一貫性、拡張性、経済効率性を実現できるプラットフォームを評価しています。ライセンスの変更、コスト最適化の目標、データセンターの変革イニシアチブ、あるいはハイブリッドクラウドの柔軟性向上へのニーズなど、理由は様々ですが、組織は移行を簡素化し、仮想化環境の持続可能な将来への道筋を提供するソリューションをますます求めるようになっています。



[[nutanix-cloud-platform]]
=== Nutanix Cloud Platform

Nutanix Cloud Platform（NCP）は、一貫したハイブリッド マルチクラウド運用モデルを提供し、共通の管理、運用、ガバナンスを維持しながら、組織がオンプレミス環境とパブリック クラウド全体でアプリケーションとデータを実行できるようにします。Nutanixのソフトウェアで定義されるアーキテクチャを活用することで、お客様はワークロードを環境全体にシームレスに拡張し、インフラストラクチャ管理を簡素化して、運用の複雑さを軽減できます。



[[the-compute-and-storage-scaling-challenge]]
=== コンピューティングとストレージのスケーリングに関する課題

仮想化環境における共通の課題は、コンピューティングとストレージの要件のバランスを取ることです。従来のアーキテクチャでは、多くの場合、組織は追加のストレージ容量を確保するためだけにコンピューティングリソースを拡張する必要があり、結果としてインフラストラクチャコストが増加します。ストレージを大量に消費するワークロードでは、CPUやメモリのリソースを追加するよりも、追加の容量とパフォーマンスを必要とすることがよくあります。



[[how-ontap-addresses-the-challenge]]
=== ONTAPが課題にどのように対処するか

ここで、NetApp ONTAPストレージとNutanix Cloud Platformの統合が大きな価値をもたらします。ONTAPは、ハイパフォーマンス、効率性、データ保護、セキュリティ、拡張性などのエンタープライズクラスのストレージ機能を提供すると同時に、ストレージ容量とパフォーマンスをNutanixのコンピューティング インフラストラクチャとは独立して拡張できるようにします。



[[example-scenario]]
=== シナリオの例

次のシナリオを考えてみましょう：お客様がアプリケーションのコンピューティング要件（vCPUとメモリ）を満たすために、8ノードに相当するインフラストラクチャリソースを必要としています。しかし、データ量の急速な増加とストレージを大量に消費するアプリケーションのため、組織は従来であれば追加のノードを導入する必要があったほどのストレージ容量を必要としています。これは、お客様がストレージ要件を満たすためだけに、追加のコンピューティングリソースを購入しなければならないため、総所有コスト（TCO）を増加させます。ONTAPをNutanix環境に統合することで、組織はストレージを個別に拡張できる真に分離されたアーキテクチャを提供し、不要なコンピューティングの拡張を行うことなく、必要な容量とストレージパフォーマンスを提供できます。



[[supported-workloads-and-use-cases]]
=== サポートされているワークロードとユースケース

この機能は、ビジネス クリティカルなデータベース、ERPプラットフォーム、Microsoftアプリケーション、仮想デスクトップインフラストラクチャ（VDI）、分析ワークロード、AI/ML環境、ファイルサービス、最新のコンテナ化アプリケーションなど、幅広いエンタープライズアプリケーションの展開に役立ちます。また、ワークロード移行、災害復旧、開発・テスト環境、データ保護、サイバーレジリエンスといった主要なインフラストラクチャ関連の取り組みもサポートします。コンピューティングリソースとストレージリソースを独立してスケーリングできるようにすることで、組織はインフラストラクチャへの投資を最適化し、コンピューティングクラスタ間で共通の高密度ストレージプールを共有しながら、従来型アプリケーションと最新アプリケーションの両方のパフォーマンス、可用性、および容量要件を満たすことができます。



[[what-this-solution-covers]]
=== このソリューションがカバーする内容

このソリューションでは、ONTAPストレージをプロビジョニングしてNutanix Cloud Platformと統合し、コスト、拡張性、パフォーマンスを最適化しながら仮想化ワークロードにNFSベースのストレージを使用できるようにするために必要な手順について説明します。



[[high-level-architecture]]
== 高レベルアーキテクチャ

このアーキテクチャでは、Nutanixコンピューティングクラスタが、Nutanixクラスタ全体で仮想マシンを実行するAHVハイパーバイザーを使用してコンピューティング レイヤを提供する一方で、ONTAPが外部共有ストレージ レイヤを提供します。仮想マシンのディスクとデータは、Nutanixホストが直接マウントするNetApp NFSv3データストアに格納されます。

NutanixはVM I/Oのハイパフォーマンス データ パスとしてNFSv3を使用し、ONTAP REST APIはストレージ プロビジョニング、管理、自動化に使用されます。ONTAPは、Nutanixのコンピューティング インフラストラクチャとは独立して、スナップショット、クローニング、レプリケーション、ストレージ効率化、無停止運用などのエンタープライズクラスのデータ サービスを提供します。

image:nutanix-overview-001.png["NFSv3とONTAP REST APIを使用してNetApp ONTAP 9クラスタに接続された3つのAHVノードを持つNutanixコンピューティング クラスタのアーキテクチャ図"]

この分離型アーキテクチャにより、お客様はコンピューティングとストレージを個別に拡張し、ストレージ利用率を最適化して、ONTAPの実績ある耐障害性とデータ保護機能を活用できるようになります。このソリューションはNetApp AFFおよびFASプラットフォームをサポートし、仮想化ワークロード、プライベートクラウド環境、ビジネス クリティカルなアプリケーションに柔軟な基盤を提供します。



[[requirements]]
== 要件

NutanixコンピューティングクラスタでONTAPストレージを展開する前に、以下の要件を確認してください。

* 最低3ノードのコンピューティングクラスタが必要です。
* ONTAPでは、ストレージ仮想マシン（SVM）がコンピューティングクラスタにストレージを提供します。
* 各FlexVol volumeは、NFSv3共有またはエクスポートとしてエクスポートされます。




[[configuration-limitations-and-considerations]]
== 構成上の制限事項と考慮事項

NutanixおよびONTAPの構成を計画する際は、以下の制限事項と設計上の考慮事項に留意してください。

* ONTAP外部ストレージは、新規または既存のNutanix HCIクラスタに接続できません。Nutanixコンピュートクラスタは、HCI構成または外部ストレージ構成で展開できますが、コンピュートクラスタで両方の構成を同時に使用することはできません。既存のHCI環境に外部ストレージを追加するには、ノードを完全に再展開する必要があります。
* 単一のONTAPクラスタからNutanixコンピューティング専用クラスタに追加できるONTAP SVMは1つだけです。
* ストレージコンテナを接続する場合、SVMごとに使用できるLIFは1つのみです。
* ONTAPのSnapMirrorベースのディザスタリカバリとFlexVolベースのスナップショットリカバリはサポートされていません。
* 1つのONTAPクラスタは、ストレージ容量、パフォーマンス、および設計要件に応じて、複数のNutanixコンピュートクラスタで使用できます。
