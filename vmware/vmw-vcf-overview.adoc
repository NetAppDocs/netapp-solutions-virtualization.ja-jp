= VMware Cloud Foundation と ONTAP でプライベートクラウドエクスペリエンスを強化
:hardbreaks:
:allow-uri-read: 
:nofooter: 
:icons: font
:linkattrs: 
:imagesdir: ../media/


[role="lead"]
NetApp ONTAPはVMware Cloud Foundation（VCF）と統合することで、ブロック、ファイル、オブジェクトプロトコルをサポートする統合ストレージソリューションを提供します。ONTAPのマルチテナンシー機能により、組織はワークロードを統合して管理を簡素化しながら、エンタープライズクラスのデータ保護と可用性を実現できます。このドキュメントでは、VCFの概要と、NetApp ONTAPをVCF環境内のストレージ機能の強化に活用する方法について説明します。



[[introduction]]
== はじめに

VCFを利用することで、組織はプライベートクラウド環境を容易に導入・管理できるようになります。標準機能として、VM、Kubernetes、コンテナ、ネットワークをサービスとして提供し、セルフサービスポータルでカタログアイテムとして他のサービスを提供するように拡張することも可能です。VCF内のストレージソリューションとしてNetApp ONTAPを活用することで、組織はワークロードの管理においてより高い柔軟性、拡張性、および効率性を実現できます。



[[introduction-to-netapp-ontap]]
== NetApp ONTAPの紹介

NetApp ONTAPは、幅広い製品ラインにわたって高度なストレージ機能を提供する包括的なデータ管理ソフトウェアです。ONTAPは、ソフトウェア定義ストレージとして、主要なクラウドプロバイダーを通じたファーストパーティサービスとして、またNetApp ASA （ブロック最適化向け分解型）、AFX （非構造化データ向け分解型）、AFF & FAS （統合）プラットフォームのストレージOSとして利用可能です。ONTAPは、サイロ化を生じさせることなく、VMware仮想化を含む様々なユースケースに対してハイパフォーマンスと低レイテンシを提供します。コンピューティング上でVMが作成されたのと同様に、ONTAPはストレージリソースの作成と管理に使用できるストレージ仮想マシン（SVM）の作成を可能にします。ONTAPは、NFS、SMB、iSCSI、FC、NVMe/TCP、NVMe/FC、NVMe/RDMAなど、複数のプロトコルをサポートする統合ストレージソリューションを提供します。この柔軟性により、組織はエンタープライズクラスのデータ保護と可用性を維持しながら、ワークロードを統合し、管理を簡素化することができます。



[[introduction-to-vmware-cloud-foundation]]
== VMware Cloud Foundation の概要

VMware Cloud Foundation (VCF) は、AI ワークロード、DevOps、または従来のVMベースのワークロードに関わらず、組織が仮想プライベートクラウドを作成し、VM、Kubernetesクラスター、コンテナ、仮想ネットワーク、ストレージをサービスとして利用できるようにします。

VCFは、新規環境または既存のvSphere環境を完全なプライベートクラウドに拡張するために導入されます。一連のコンピュートホストがvSphereクラスターを形成し、vSphereクラスターのグループがVCFドメインを形成し、VCFドメインのグループがVCFインスタンスを形成します。フリートは、1つ以上のVCFインスタンスで構成されます。VCFプライベートクラウド環境は、1つまたは複数のフリートを使用して作成されます。運用と自動化はフリートレベルで処理され、VCFインスタンスはデプロイメントの単位となります。

A vSphere 名前空間は、ワークロードのリソース制限を設定するために使用されます。A vSphere Zone は、ゾーン内で実行されているワークロードに対して高可用性とディザスタリカバリ機能を提供するために使用できる vSphere クラスターのコレクションです。

image:vmware-vcf-overview-components.png["VMware Cloud Foundation コンポーネント"]

VCF Automationでは、リージョンとは、同じNSXインフラストラクチャを共有する1つ以上のVCFドメインからのvSphereゾーンのコレクションです。組織とは、1つまたは複数のリージョンに属するユーザーとリソースを論理的にグループ化したものです。組織は複数のプロジェクトに細分化でき、それぞれのプロジェクトは独自のトランジットゲートウェイと外部接続を備えています。プロジェクトには1つ以上の名前空間があり、プロジェクト内で実行されるワークロードの分離とリソース割り当てを提供するために使用できます。

名前空間は、プロジェクト内におけるリソース割り当ての基本単位です。各ネームスペースは仮想プライベートクラウド（VPC）に対応しており、ネームスペース内で実行されるワークロードの分離とリソース割り当てを提供するために使用できます。

名前空間は、専用VPCまたは共有VPCを使用して作成されます。専用VPCとは、単一の名前空間専用のVPCであり、共有VPCとは、複数の名前空間で使用できるVPCのことです。ワークロードがデプロイされるVPC内にサブネットが作成されます。

ストレージは、vCenter で定義されたストレージポリシーベース管理（SPBM）ポリシーによって消費されます。SPBMは、ワークロードのストレージ要件を定義する一連のルールを使用して作成できます。データストアは通常タグ付けされ、さまざまなワークロードの特定のニーズに合わせたストレージポリシーを作成するために利用されます。

アフィニティルールとアンチアフィニティルールを必要とするワークロードは、vCenterのコンピューティングポリシーを使用してワークロードを特定のホストまたはクラスタに配置する方法を定義するインフラストラクチャポリシーによって管理されます。インフラストラクチャポリシーを使用することで、ワークロードを要件に基づいて特定のホストまたはクラスタに配置することができます。



[[vcf-domains]]
== VCF ドメイン

ドメインは、VCF 内の基本的な構成要素であり、リソースを個別の独立したグループに編成することを可能にします。ドメインはインフラストラクチャをより効果的に整理し、リソースが効率的に利用されるようにするのに役立ちます。各ドメインは、独自のコンピューティング、ネットワーク、およびストレージ要素とともに展開されます。

image:vmware-vcf-overview-domains.png["VMware クラウドドメイン"]

VCF には主に 2 つのタイプのドメインがあります。

* *管理ドメイン* – 管理ドメインには、VCF環境の中核機能を担うコンポーネントが含まれます。これらのコンポーネントは、リソースのプロビジョニング、監視、メンテナンスなどの重要なタスクを処理し、VMware向けNetApp ONTAP Toolsなどのサードパーティプラグイン統合も含まれます。管理ドメインは、ベストプラクティスが確実に遵守されるようにVCFインストーラアプライアンスを使用して展開することも、既存のvCenter環境をVCF管理ドメインに変換することもできます。
* *ワークロードドメイン* – ワークロードドメインは、特定の運用ニーズ、ワークロード、または組織に特化したリソースのプールとして設計されています。ワークロードドメインはOPS Managerを介して簡単に展開でき、一連の複雑なタスクの自動化に役立ちます。VCF環境内では最大24個のワークロードドメインをプロビジョニングでき、それぞれがアプリケーション対応インフラストラクチャの単位を表します。各ワークロードドメインは、独自のNSXインフラストラクチャを持つか既存のインフラストラクチャを共有するかは、単一リージョン展開か複数リージョン展開かによって異なります。




[[storage-with-vcf]]
== VCFによるストレージ

ドメインの機能の中心となるのは、ドメインが消費するストレージです。 VCF にはハイパーコンバージド ユースケース向けの CPU コア ベースの vSAN 容量が含まれているだけでなく、幅広い外部ストレージ ソリューションもサポートしています。この柔軟性は、既存のストレージ アレイに多額の投資を行っている企業や、vSAN がサポートできる範囲を超えたプロトコルをサポートする必要がある企業にとって非常に重要です。  VMware は、VCF で複数のストレージ タイプをサポートしています。

VCF には主に 2 つのタイプのストレージがあります。

* *プライマリストレージ* – このストレージタイプは、新しいVCFドメインのDay 0デプロイメントの一部として、または既存のvCenterのコンバージェンスまたはインポートの一部として自動的にプロビジョニングされます。VCFインストーラーは、新規導入時にVSAN、FC上のVMFS、NFSをサポートしますが、iSCSI上のVMFS、NVMe-oFなどのその他のサポート対象ストレージタイプは、既存のvCenterのコンバージェンスまたはインポートの一部としてプライマリストレージとして使用できます。ONTAP Tools for VMware vSphereは、VCFドメインのプライマリストレージをデプロイするために、既存のvCenterのコンバージェンスまたはインポートにのみ使用できます。追加のクラスタ展開の一環として、またはドメイン拡張の一環として作成されたデータストアは、すべてプライマリストレージとみなされます。プライマリストレージは、vCenter、NSX Manager、SDDC Managerなどのなどの VCF管理コンポーネントと、ドメイン内で実行されているワークロードをホストするために使用されます。
* *補助ストレージ* – 補助ストレージとは、VCFドメインの初期展開後、または既存のvCenter環境の統合やインポート後にプロビジョニングされるデータストアのことです。補助ストレージは、ONTAP Tools for VMware vSphereを使用して、VCFドメイン用のデータストアをデプロイすることで作成できます。補助ストレージは、追加の容量ニーズ、パフォーマンス要件に対応するため、または異なるストレージ特性を必要とする特定のワークロードをサポートするために作成されます。高可用性を実現するために、補助ストレージを作成してストレッチクラスターを構築することも可能です。


*VCFストレージタイプをサポート*

[cols="25%, 25%, 50%"]
|===


| *ドメインタイプ* | *プリンシパルストレージ* | *補助ストレージ* 


| 管理ドメイン | vSAN FC NFS 3 NFS 4.1 ^2^ iSCSI ^2^ NVMe/TCP ^2^ NVMe/FC ^2^ NVMe/RDMA ^2^ | vVols （FC、iSCSI、またはNFS） ^1^ FC NFS 3 NFS 4.1 iSCSI NVMe/TCP NVMe/FC NVMe/RDMA 


| ワークロードドメイン | vSAN vVols （FC、iSCSI、またはNFS） ^1^ FC NFS 3 NFS 4.1 ^2^ iSCSI ^2^ NVMe/TCP ^2^ NVMe/FC ^2^ NVMe/RDMA ^2^ | vVols（FC、iSCSI、またはNFS） ^1^ FC NFS 3 NFS 4.1 iSCSI NVMe/TCP NVMe/FC NVMe/RDMA 
|===

NOTE: ^1^ vVol サポートは vSphere 環境では非推奨です。^2^ Converge またはインポートオプションを使用



[[why-ontap-for-vcf]]
== ONTAPがVCFに選ばれる理由

投資保護やマルチプロトコル サポートを含むユース ケースに加えて、VCF ワークロード ドメイン内で外部共有ストレージを活用する理由は他にも多数あります。ワークロード ドメイン用にプロビジョニングされたストレージは、VM とコンテナをホストするためのリポジトリにすぎないと考えられるかもしれません。ただし、組織のニーズがライセンス容量の能力を超え、エンタープライズ ストレージが必要になることがよくあります。  ONTAPによって提供され、VCF 内のドメインに割り当てられるストレージは、導入が簡単で、将来を見据えた共有ストレージ ソリューションを提供します。

image:why-ontap-for-vmware-002.png["ONTAPがVCFに選ばれる理由"]

以下に挙げたVMware VCFにおけるONTAPの主なメリットの詳細については、以下を参照してください。link:vmw-getting-started-overview.html#why-ontap-for-vmware["ONTAP for VMwareを選ぶ理由"] 。

* 初日から拡張まで柔軟に対応
* ストレージタスクをONTAPにオフロードする
* クラス最高のストレージ効率
* エンタープライズグレードのデータ可用性
* 効率的なバックアップとリカバリ操作
* 包括的な事業継続機能

[[summary]]
== まとめ

ONTAP は、すべてのワークロード要件に対応するプラットフォームを提供し、カスタマイズされたブロック ストレージ ソリューションと統合されたサービスを提供することを通じて、信頼性とセキュリティに優れた方法で VM とアプリケーションの結果をより迅速に実現します。 ONTAP には、データセンターの占有スペースを最小限に抑える高度なデータ削減および移動技術が組み込まれており、同時にエンタープライズ レベルの可用性を確保して重要なワークロードをオンライン状態に維持します。さらに、AWS、Azure、Google は、VMware-in-the-Cloud サービスの一部として、VMware クラウドベース クラスタ内の vSAN ストレージを強化するために、 NetApp搭載の外部ストレージをサポートしています。全体的に、NetApp の優れた機能により、VMware Cloud Foundation の導入にとってより効果的な選択肢となります。
