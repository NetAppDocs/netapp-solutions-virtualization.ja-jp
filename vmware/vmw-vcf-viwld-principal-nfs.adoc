= ONTAP上のNFSデータストアをVCFワークロードドメインのプリンシパルストレージとして使用する
:hardbreaks:
:allow-uri-read: 
:nofooter: 
:icons: font
:linkattrs: 
:imagesdir: ../media/


[role="lead"]
このユースケースでは、VMware Cloud Foundation （VCF）ワークロード ドメインの主要ストレージ ソリューションとして、ONTAP 上に NFS データストアを構成する手順を概説します。この手順では、必要なコンポーネント、構成手順、および導入プロセスをまとめます。



[[benefits-of-nfs]]
== NFSの利点

*シンプルさと使いやすさ:* NFS はセットアップと管理が簡単なので、迅速かつ簡単なファイル共有を必要とする環境に最適です。

*スケーラビリティ:* ONTAP のアーキテクチャにより、NFS は効率的に拡張でき、インフラストラクチャに大きな変更を加えることなく増大するデータ ニーズに対応できます。

*柔軟性:* NFS は幅広いアプリケーションとワークロードをサポートしており、仮想化環境を含むさまざまなユースケースに幅広く対応できます。



[[scenario-overview]]
== シナリオの概要

このシナリオでは、次の大まかな手順について説明します。

* NFSトラフィック用の論理インターフェース（LIF）を備えたストレージ仮想マシン（SVM）を作成する
* ONTAPストレージ仮想マシン (SVM) のネットワークを確認し、NFS トラフィックを伝送するための論理インターフェイス (LIF) が存在することを確認します。
* エクスポートポリシーを作成して、vSphereホストが NFS ボリュームにアクセスできるようにします。
* ONTAPストレージ システムに NFS ボリュームを作成します。
* SDDC Manager で NFS および vMotion トラフィック用のネットワーク プールを作成します。
* vCenter のホストを VCF ワークロード ドメインで使用するためにコミッションします。
* NFSデータストアを主要ストレージとして使用して、VCF OpsにVCFワークロードドメインをデプロイします。
* クラスターイメージに NetApp NFS Plug-in for VMware VAAI が含まれていることを確認してください。



NOTE: このソリューションは、NFSストレージをサポートするONTAPプラットフォーム（NetApp AFF、AFX、FASを含む）に適用できます。



[[prerequisites]]
== 前提条件

このシナリオでは、次のコンポーネントと構成が使用されます。

* NetApp AFF、AFX、またはFASストレージ システム（NFSトラフィックを許可するように構成されたストレージ仮想マシン（SVM）を使用）。
* NFS トラフィックを伝送し、SVM に関連付けられた IP ネットワーク上に論理インターフェイス (LIF) が作成されています。
* VCF管理ドメインの展開が完了し、VCF Operations Managerのインターフェースにアクセスできるようになりました。
* VCF管理ネットワーク上での通信用に設定された、少なくとも2台のvSphereホスト。
* この目的のために確立された VLAN またはネットワーク セグメント上の vMotion および NFS ストレージ トラフィック用に予約された IP アドレス。



NOTE: VCF ワークロード ドメインをデプロイする際、VCF は NFS サーバーへの接続性を検証します。これは、NFS IP アドレスを持つ追加の vmkernel アダプタが追加される前に、vSphere ホストの管理アダプタを使用して行われます。したがって、検証を続行できるようにするには、1） 管理ネットワークが NFS サーバーにルーティング可能であること、または 2） 管理ネットワーク用の LIF が NFS データストア ボリュームをホストする SVM に追加されていることを確認する必要があります。

ONTAPストレージシステムの構成については、link:https://docs.netapp.com/us-en/ontap["ONTAP 9ドキュメント"]中心。

VCF の設定方法については、link:https://techdocs.broadcom.com/us/en/vmware-cis/vcf/vcf-9-0-and-later/9-1.html["VMware Cloud Foundation ドキュメント"]を参照してください。

vSphereクラスタでNFSを使用する方法の詳細については、link:vmw-vvf-overview.html["vSphere 8 向け NFS v3 リファレンス ガイド"] 。

[[deployment-steps]]
== 展開手順

NFSv3データストアをプライマリストレージとして使用するVCFワークロードドメインをデプロイするには、以下の手順を実行します。

.ONTAP SVMのネットワークを確認する
[%collapsible%open]
====
ONTAPストレージクラスタとワークロードドメイン間でNFSトラフィックを伝送するネットワークに、必要な論理インターフェースが確立されていることを確認します。

. ONTAP System Manager の左側メニューで *Storage VMs* に移動し、NFS トラフィックに使用する SVM をクリックします。*Overview* タブの *Network interfaces* で、*NFS* ラベルの上にある数字をクリックします。リストに、必要な LIF IP アドレスが記載されていることを確認します。
+
image:vmw-vcf-viwld-principal-nfs-001.png["SVMのNFS LIFを検証する"]



または、次のコマンドを使用して、 ONTAP CLI から SVM に関連付けられている LIF を確認します。

[source, cli]
----
network interface show -vserver <SVM_NAME>
----
. vSphere ホストが ONTAP NFS サーバーと通信できることを確認してください。SSH 経由で vSphere ホストにログインし、SVM LIF に ping を実行します：


[source, cli]
----
vmkping <IP Address>
----

NOTE: ワークロード ドメインをデプロイする際、VCF は NFS サーバーへの接続性を検証します。これは、NFS IP アドレスを持つ追加の vmkernel アダプタが追加される前に、vSphere ホスト上の管理アダプタを使用して行われます。したがって、検証を続行できるようにするには、1） 管理ネットワークが NFS サーバーにルーティング可能であること、または 2） NFS データストア ボリュームをホストする SVM に管理ネットワーク用の LIF が追加されていることを確認する必要があります。

====
.NFSボリュームを共有するためのエクスポートポリシーを作成する
[%collapsible%open]
====
ONTAP System Manager でエクスポート ポリシーを作成し、NFS ボリュームのアクセス制御を定義します。

. ONTAP System Manager で、左側のメニューの *Storage VMs* をクリックし、リストから SVM を選択します。
. *設定*タブで*エクスポート ポリシー*を見つけて、矢印をクリックしてアクセスします。
+
image:vmw-vcf-viwld-principal-nfs-002.png["輸出ポリシーにアクセスする"]

+
{nbsp}

. 「追加」をクリックすると、「新しいエクスポートポリシー」ウィンドウが開きます。ポリシーの名前を追加し、「新しいルールを追加」ボタンをクリックしてから、「+追加」ボタンをクリックして新しいルールの追加を開始します。
+
image:vmw-vcf-viwld-principal-nfs-003.png["新しい輸出政策"]

+
{nbsp}

. ルールに含めるIPアドレス、IPアドレス範囲、またはネットワークを入力してください。*SMB/CIFS* と *FlexCache* のチェックを外し、以下のアクセスの詳細を選択してください。UNIXボックスを選択するだけで、vSphereホストアクセスには十分です。
+
image:vmw-vcf-viwld-principal-nfs-004.png["新しいルールを保存"]

+

NOTE: ワークロードドメインをデプロイする際、VCF はNFSサーバーへの接続性を検証します。これは、NFS IP アドレスを持つ追加の vmkernel アダプタが追加される前に、vSphere ホストの管理アダプタを使用して行われます。したがって、検証を進めるためには、エクスポートポリシーに VCF 管理ネットワークを含めることが必要です。

. すべてのルールを入力したら、[*保存*] ボタンをクリックして新しいエクスポート ポリシーを保存します。
. あるいは、 ONTAP CLI でエクスポート ポリシーとルールを作成することもできます。  ONTAPドキュメントでエクスポート ポリシーを作成し、ルールを追加する手順を参照してください。
+
** ONTAP CLIを使用してlink:https://docs.netapp.com/us-en/ontap/nfs-config/create-export-policy-task.html["エクスポート ポリシーの作成"]。
** ONTAP CLIを使用してlink:https://docs.netapp.com/us-en/ontap/nfs-config/add-rule-export-policy-task.html["エクスポート ポリシーへのルールの追加"]。




====
.NFSボリュームを作成する
[%collapsible%open]
====
ワークロード ドメインのデプロイメントでデータストアとして使用する NFS ボリュームをONTAPストレージ システム上に作成します。

. ONTAP System Manager から、左側のメニューの *Storage > Volumes* に移動し、*+Add* をクリックして新しいボリュームを作成します。
+
image:vmw-vcf-viwld-principal-nfs-005.png["新しいボリュームを追加"]

+
{nbsp}

. ボリュームの名前を追加し、必要な容量を入力して、ボリュームをホストするストレージ VM を選択します。続行するには、[*その他のオプション*] をクリックします。
+
image:vmw-vcf-viwld-principal-nfs-006.png["ボリュームの詳細を追加する"]

+
{nbsp}

. [アクセス許可] で、NFS サーバーと NFS トラフィックの両方の検証に使用される VCF 管理ネットワークまたは IP アドレスと NFS ネットワーク IP アドレスを含むエクスポート ポリシーを選択します。
+
image:vmw-vcf-viwld-principal-nfs-007.png["ボリュームの詳細を追加する"]

+
+

+

NOTE: VCF ワークロード ドメインをデプロイする際、VCF は NFS サーバーへの接続性を検証します。これは、NFS IP アドレスを持つ追加の vmkernel アダプタが追加される前に、vSphere ホストの管理アダプタを使用して行われます。したがって、検証を続行できるようにするには、1） 管理ネットワークが NFS サーバーにルーティング可能であること、または 2） 管理ネットワーク用の LIF が NFS データストア ボリュームをホストする SVM に追加されていることを確認する必要があります。

. または、ONTAP CLI で NFS ボリュームを作成することもできます。詳細については、ONTAP コマンドのドキュメントに記載されている link:https://docs.netapp.com/us-en/ontap-cli/volume-create.html["volume create"] コマンドを参照してください。


====


[[vcf-workload-domain-default-cluster]]
=== VCF Workload Domain - デフォルト クラスター

管理ドメインが稼働状態になったら、VCF ワークロード ドメインを作成できます。

* VCF Ops UI を使用します。vSphere ホストは vCenter にコミッションされ、ネットワークプールが設定されています。System Manager または ONTAP API を使用して、NFS ボリュームを vSphere ホストにエクスポートします。
* 既存のvSphere環境を新しいワークロードドメインとしてインポートします。ONTAP tools for VMware vSphere、System Manager、またはONTAP APIを使用して、NFSv3またはNFS4.1データストアをvSphereクラスタにデプロイできます。




[[vcf-workload-domain-additional-cluster]]
=== VCFワークロード ドメイン - 追加クラスター

ワークロードドメインにクラスターを追加するには、 https://techdocs.broadcom.com/us/en/vmware-cis/vcf/vcf-9-0-and-later/9-1/building-your-private-cloud-infrastructure/working-with-workload-domains/expand-a-workload-domain/add-a-cluster-to-a-workload-domain-using-the-sddc-manager-ui.html["SDDCクラスタをVCFドメインに追加する"]を参照してください。

大まかに言うと、ワークロード ドメインにクラスターを追加する手順は次のとおりです。* ホストがコミッショニングされ、ネットワーク プールが vCenter で構成されていることを確認します。* NFS ボリュームは ONTAP ストレージ システムにプロビジョニングされ、追加クラスター内のホストにエクスポートされます。* NFS ボリュームは、追加クラスター内のいずれかの vSphere ホストにマウントされます。* vCenter のワークロード ドメインで新しい SDDC クラスターを作成し、ウィザードに従って追加のクラスターをワークロード ドメインに追加します。
