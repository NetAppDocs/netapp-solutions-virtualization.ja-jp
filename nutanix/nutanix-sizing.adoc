= Nutanix AHV移行用のONTAPストレージのサイジング
:hardbreaks:
:allow-uri-read: 
:nofooter: 
:icons: font
:linkattrs: 
:imagesdir: ../media/


[role="lead"]
NetApp ONTAP外部ストレージを使用してVMwareワークロードをNutanix AHVに移行する場合は、コンピューティングとストレージのサイジングを個別に実施してください。Nutanixのコンピューティングサイジングでは、各ノードのController VM（CVM）が使用するリソースを含め、必要なAHVノード数と構成を決定します。ONTAPのサイジングでは、ストレージ容量、パフォーマンス、可用性に対応します。



[[discover-vmware-workload-requirements]]
== VMwareワークロードの要件を確認する

VMware vCenterから、以下を含む30～90日間のVMレベルのパフォーマンスデータを収集します：

* *コンピューティング*：vCPU、CPU使用率、メモリ割り当て、および最大メモリ需要。
* *ストレージ容量*：プロビジョニング済みおよび使用済みのディスク容量。
* *ストレージパフォーマンス*：読み取り / 書き込みIOPS、読み取り / 書き込みスループット、平均I/Oサイズ、およびレイテンシ。
* *ワークロードパターン*：ピーク期間、同時ワークロード、読み取り / 書き込み分布。


サイジング対象のワークロードには、測定された平均I/Oサイズを使用してください。すべてのNutanixワークロードに対して、8 KiBや16 KiBといった単一のブロックサイズを想定するべきではありません。



[[size-nutanix-compute]]
== Nutanixコンピューティングのサイズ

仮想マシンのCPUとメモリの需要の合計からlink:https://sizer.nutanix.com/["AHVノードの要件"^]を計算します。各ノードのCVM用に予約されたCPUとメモリ、およびCPUをオーバーコミットする、高可用性要件、予想される成長を含めてください。Nutanixが推奨するCVMリソース予約を適用して、各ノードの利用可能容量にそれらが反映されるようにしてください。

CPUとメモリのノード要件は別々に計算してください。より大きな見積もり値が、初期クラスター要件を決定します。結果として得られた構成を、NutanixのサイジングガイドラインおよびHA要件に照らして検証してください。



[[size-ontap-storage-performance]]
== ONTAPストレージパフォーマンスのサイジング

以下の手順に従って、ワークロードに必要なIOPS、スループット、レイテンシ、およびコントローラの要件を決定してください。

. *集計ワークロードIOPSを計算します。*
+
共通の時間間隔でVM全体の読み取りおよび書き込みIOPSを集計し、実際の同時ピークを特定します。すべてのVMが同時に個別のピークに達すると仮定するのではなく、観測された総需要を使用してください。VMのディスクレベルの統計情報を収集するには、link:https://docs.netapp.com/us-en/netapp-solutions-virtualization/vmware/vmw-getting-started-vmdc.html["NetApp仮想マシンデータコレクター（VMDC）"^]、Live Optics、または任意の監視ツールを使用してください。

+
ワークロードプロファイルの例：

+
** VMの数：500
** VMあたりの平均IOPS：100
** アグリゲートの平均IOPS：50,000
** 観測されたピークIOPS：100,000
** 読み取り / 書き込み比率：70% / 30%
** 平均I/Oサイズ：ワークロードデータから測定


. *スループットを計算します。*
+
利用可能な場合は、測定された読み取り / 書き込みスループットを使用します。それ以外の場合は、測定されたI/Oサイズを使用して推定します：

+
`Throughput = IOPS × Average I/O Size`

+
I/Oサイズが異なる場合は、読み取りスループットと書き込みスループットを別々に計算してください。

. *レイテンシ要件を設定します。*
+
過去のVMwareのパフォーマンスとアプリケーション要件に基づいて目標を設定します。具体的な目標値としては、汎用仮想マシンでは5ミリ秒以下、パフォーマンス重視のアプリケーションでは2ミリ秒以下、一部の重要なデータベースでは1ミリ秒未満などが挙げられます。これらはサービス目標であり、ONTAPのパフォーマンスレベルを保証するものではありません。最終的な要件は、アプリケーションのSLAを反映する必要があります。

. *ワークロードの増加を適用します。*
+
予想される成長率を含め、パフォーマンスの変動性、バックグラウンドオペレーション、およびスナップショットアクティビティを評価します。例えば、100,000 IOPSのベースラインに対して30%の成長を想定すると、130,000 IOPSが必要になると予測されます。

. *ONTAPコントローラーを選択します。*
+
目標レイテンシで必要となる読み取り / 書き込みIOPS、スループットとネットワーク帯域幅、I/O特性、ストレージ効率、バックグラウンド処理、フェイルオーバーパフォーマンス、および予想される成長に基づいて、AFFプラットフォームを選択します。NetAppがサポートするサイジングツールとプラットフォームのパフォーマンスデータを使用して、構成を検証します。IOPSだけでは、コントローラの選択を決定するには不十分です。





[[size-ontap-capacity]]
== ONTAP容量のサイジング

VMwareのディスク使用量、予測される増加量、スナップショットの保持期間、および予想されるストレージ効率から容量を推定します。ストレージ効率比2：1は計画上の前提条件として使用できますが、実際の結果はワークロードと構成によって異なります。スナップショットと保護容量は、恣意的な許容値を適用するのではなく、意図した保持期間とワークロードの変化率に基づいて計算します。

容量計算例：

* 500 VMs × 100 GiB 消費：48.8 TiB 論理
* ワークロードが30%増加した後：63.5 TiBの論理データ
* 2:1効率における推定物理データ：31.7 TiB
* 利用率80%における推定設置済み使用可能容量：39.7 TiB


80%の稼働率という数字は、容量を確保するためのものです。これは、追加の20%の運用オーバーヘッドではありません。NetAppソリューションアーキテクトまたは指定されたNetAppパートナーと、データ削減の前提条件、実効容量、およびプラットフォームのオーバーヘッドを検証してください。担当者はNetApp Fusionを使用してONTAPシステムのサイジングを行い、容量、パフォーマンス、および可用性の要件を確認できます。
